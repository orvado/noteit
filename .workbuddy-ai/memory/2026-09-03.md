# 2026-09-03 — Invisible cursor / blank editor pane fix in NoteIt

## Root cause
NSTextView rasterizes its drawn text into an internal CALayer keyed to the
*current* visible rect. When that rect changes — e.g. an NSRulerView makes
NSScrollView reposition the clip view, or the gutter is toggled on/off so the
clip view's width changes — the content layer keeps its old `position` and
`bounds`. The text view is in the right place, the data is correct, focus
works, glyphs are laid out — but the rasterized text sits at the stale
geometry, so the editor pane paints blank.

## Fix (in Sources/NoteIt/EditorView.swift)
- Replaced `NSRulerView` line-number ruler with a sibling `LineNumberGutterView`
  (NSView, flipped, draw-line-numbers-from-layout-manager). Sidesteps the
  scroll-view clip geometry mangling entirely.
- Added an `EditorContainerView` that owns the gutter + NSScrollView and
  arranges them in `layout()`.
- Final piece: in `EditorContainerView.layout()`, after any geometry change,
  "jiggle" the text view's frame size (`setFrameSize(h+1)` then `setFrameSize(h)`)
  so NSTextView's content layer invalidates and redraws. Without this, toggling
  the gutter hides/shows still left the pane blank even though no ruler was
  involved.

## Verification (since cleaned up)
- Wrote a temp `__Verify.swift` harness with a screenshot hook driven from
  `NoteItApp.onAppear` via `VerifyStore.shared`.
- 6 screenshots: wrap-on/lines-on, typed caret, scrolled-bottom gutter follows,
  wrap-off (with long line to confirm horizontal scroll), lines-off, lines-back-on.
- Deep dump revealed the stale contentLayer geometry (e.g. bounds=900x355 when
  clip view was actually 869 wide).
- Removed all temp code and rebuilt clean.

## Files touched

- Sources/NoteIt/NoteItApp.swift (restored to original after verify)

## Find-bar close (X button) fix
In `SearchReplaceBar` (Sources/NoteIt/Panels.swift):
- The X button was wired only to clear the query — never dismissed the bar.
- Added `showFind: Binding<Bool>` to `SearchReplaceBar`; the X now calls a
  `close()` helper that clears the query, clears highlights, sets both
  `showFind` and `showReplace` to false, and hands focus back to the editor.
- Also wired `Esc` via `.onExitCommand(perform: close)` so the tooltip's
  advertised shortcut works.
- Updated `ContentView` to pass `$showFind` into the bar.

Verified by a screenshot harness that synthesizes mouse events (had to use
NSEvent.mouseEvent locations in **window** coords, not screen, and route
through `NSApp.sendEvent`). Both paths dismiss the panel.

## SwiftUI click-testing pattern (reusable)
To simulate a SwiftUI `Button` click from a verification harness:
1. Walk `NSApp.keyWindow.contentView.subviews` and find the `_FocusRingView`
   matching the button's geometry (SwiftUI image buttons render as `_FocusRingView`).
2. Compute the centre: `view.convert(NSPoint(midX, midY), to: nil)` — this is
   window-base coords.
3. Build `NSEvent.mouseEvent(.leftMouseDown/.leftMouseUp, location: windowPt, ...)`.
4. Dispatch via `NSApp.sendEvent(_:)`, not `win.sendEvent(_:)` — SwiftUI's
   responder chain routes through the application.
